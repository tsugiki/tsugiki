# Use the git CLI rather than libgit2 or gitoxide

The Rust backend talks to git by running the `git` CLI as a subprocess and parsing its plumbing and `--porcelain` output. gh-rev needs `grep`, `check-attr`, `patch-id` (to tell a rebase that leaves the diff the same from a real change), `--reference` clones, partial fetch and, later, `range-diff`. libgit2 (git2-rs) lacks grep, patch-id and range-diff, has weak partial-clone support, and detects renames differently. gitoxide (`gix`) still lacks grep and range-diff. Using the CLI also guarantees that gh-rev shows exactly the diff the reviewer would get from `git diff` themselves. Spawning a process costs about 10–30 ms on Windows. If profiling ever shows that matters for a hot read path, such as streaming large blobs, `gix` can be added for that path alone.
