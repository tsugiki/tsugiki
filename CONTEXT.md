# gh-rev

A review workbench for a CPython core developer: it groups `python/cpython` PRs under the Issues they fix and tracks which of those PRs the user still owes a review.

## Language

### Work structure

**Issue**:
A CPython GitHub issue (`gh-NNNNN`) that one or more PRs fix. The PRs say so with the `gh-NNNNN:` prefix in their titles.
_Avoid_: Ticket, bug

**Origin PR**:
A PR against `main` that fixes (part of) an **Issue**; any **Backports** are made from it.
_Avoid_: Main PR, parent PR, original PR

**Backport**:
A PR that carries an **Origin PR**'s change to a maintenance **Target branch**. It is opened either by `miss-islington` or by hand, and its title carries `(GH-NNNNN)` pointing at its Origin PR.
_Avoid_: Cherry-pick, child PR

**Bot backport**:
A **Backport** opened by `miss-islington` that contains only the cherry-picked change. It shares its **Origin PR**'s review state instead of having its own.
_Avoid_: Auto backport, clean backport

**Manual backport**:
A **Backport** opened by a person, or a **Bot backport** that later got extra commits. It is reviewed on its own, because its diff can differ from the Origin PR's.
_Avoid_: Hand backport, conflicted backport

**Target branch**:
The branch a PR merges into: `main` or a maintenance branch such as `3.14`.
_Avoid_: Base, version

**Needs attention**:
The state of a PR that still needs action: it is open, or it is waiting on the user's review or re-review. A **Draft PR** only needs attention when it carries a **Review request**.
_Avoid_: Pending, todo

**Draft PR**:
A PR its author has marked as not yet ready for review. Its review state is still tracked. When it becomes ready for review, that counts as **New activity**.
_Avoid_: WIP PR

**Generated file**:
A file that CPython's `.gitattributes` marks as `generated` on the PR's **Target branch**, such as Argument Clinic output or `Python/generated_cases.c.h`.
_Avoid_: Autogenerated, derived file

**NEWS entry**:
A `Misc/NEWS.d/next/<section>/*.rst` blurb added by a PR, describing the change for the changelog. A PR can add several of them, or none.
_Avoid_: Blurb, changelog entry

### Workbench

**Workbench**:
The home list of **Issues** the user is currently following: every Issue that a **Filter** reaches, that is a **Pinned issue**, or that has an open PR the user holds a **Review** on. An Issue being closed on GitHub does not remove it.
_Avoid_: Dashboard, inbox

**Filter**:
A saved GitHub search the user defines, such as "PRs I opened" or "a colleague's open PRs". It can match Issues directly or match PRs; a matching PR pulls its **Issue** onto the **Workbench**.
_Avoid_: Query, section

**Built-in view**:
A **Workbench** list that gh-rev defines from its own states, which GitHub search cannot express: Stale reviews, New activity, and Review requests.
_Avoid_: Smart filter, saved view

**Matched PR**:
A PR inside an **Issue**'s tree that one of the user's **Filters** matched. It is listed first, ahead of the rest of the tree.
_Avoid_: Hit, result

**Pinned issue**:
An **Issue** the user has explicitly put on the **Workbench** in gh-rev. It stays there whether or not any **Filter** matches it. This is unrelated to GitHub's own "pin issue" feature on a repository.
_Avoid_: Watched issue, starred issue, subscribed issue

**No issue**:
The **Workbench** group for PRs whose titles carry no `gh-NNNNN` prefix (CPython's `skip issue` PRs).
_Avoid_: Orphans, misc

### Reviewing

**Review**:
A record that the user looked at a PR as of a specific commit. It is either a review the user submitted on GitHub (approve, request changes, or comment, line comments included) or a **Local mark**. Plain conversation comments do not count.
_Avoid_: Approval, LGTM

**Review checkout**:
A single working tree that gh-rev owns and switches to the head of whichever PR the user is reviewing, so an editor can be opened on it. It is never one of the user's own worktrees.
_Avoid_: Sandbox, scratch worktree

**Pending review**:
The user's unsubmitted GitHub review on a PR, holding their draft comments. It is not a **Review** until it is submitted.
_Avoid_: Draft review, local draft

**Local mark**:
A **Review** the user records only inside gh-rev, without leaving a trace on GitHub.
_Avoid_: Bookmark, seen flag

**Review request**:
A PR where the user is a requested reviewer or an assignee. It always counts as **Needs attention** until the user submits a review on GitHub (a **Local mark** does not clear it), even for a **Bot backport**.
_Avoid_: Assignment, ping

**Outdated thread**:
A comment thread whose lines no longer exist at the PR's current head. It stays visible together with the code it was written against, and the user's own unresolved Outdated threads are listed first during a re-review.
_Avoid_: Stale thread, orphaned comment

**Unreviewed**:
The user has not yet reviewed the PR.

**Reviewed**:
The user has reviewed the PR, and the PR has not changed since then.

**Stale review**:
A **Review** taken before the PR's own diff changed in files other than **Generated files**, through new commits or a rewritten history. A merge from `main`, a rebase that leaves the diff the same, or a change only to Generated files does not make a review stale.
_Avoid_: Outdated, dismissed

**Last seen**:
The moment the user last opened a PR or an **Issue** in gh-rev, or handed a PR off to a review tool. It is tracked per PR and per Issue; opening an Issue's tree does not update its PRs' Last seen.
_Avoid_: Last visited, read

**Alert**:
An OS notification that gh-rev raises, such as when CI finishes on an **Own PR**. The user can turn each kind of Alert off.
_Avoid_: Notification (that word means GitHub's notifications)

**Own PR**:
A PR the user authored.
_Avoid_: My PR

**New activity**:
Something that happened on a PR after the user's **Last seen**: commits, comments, or reviews by people other than the user, a failed **Bot backport**, or a change in CI status on an **Own PR** or a PR the user has a **Review** on. Other bot activity and label changes do not count. It is reported alongside the review state and never changes it.
_Avoid_: Unread, notifications
